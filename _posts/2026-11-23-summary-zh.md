### [以困惑度衡量模型智能](https://openai.com/index/perplexity-and-intelligence/) ⭐️ 8.0/10

OpenAI 在一篇题为《Perplexity and Intelligence》的文章中主张，用语言模型的困惑度和预测质量来考察智能，并将其与学习、压缩和推理联系起来。现有材料没有表明文章提出了经过验证的新方法，也没有提供足以确认其结论的实验细节，因此更准确地说，这是对一种评测视角的论述，而不是已得到独立验证的能力突破。

hackernews · acossta · 11月22日 17:06 · [社区讨论](https://news.ycombinator.com/item?id=50601525)

**「背景」** 困惑度衡量模型对序列中下一个词元的意外程度，通常由交叉熵损失推导而来，可理解为模型在候选词元上的预测不确定性。社区讨论指出，困惑度与压缩能力存在联系，而强化学习训练和推理模型的发展，使研究者开始重新评估这一简单指标在模型比较中的价值。

**「实际影响」** 对研究团队和模型开发者而言，这提供了一个可补充复杂综合评测的候选基准，但实际采用时需要明确测试集、词元化方式、上下文长度和评测条件是否一致。社区还提到 Microsoft 正在使用 OpenAI 许可的留出评测集报告 MAI-2 Base 的 log-perplexity，并将其与 GPT-5.6 Sol 基础模型比较，不过这些数字来自评论者引用的社交媒体内容，现有材料无法独立核实。

**「社区讨论」** 评论者普遍认为困惑度与智能之间的联系比直觉更自然，其中 d\_burfoot 将预测和压缩能力视为智能的重要特征，并提到自己早在 2008 年就提出过相关观点。jrflo 则认为，在强化学习和复杂评测不断增加的背景下，重新重视交叉熵损失和困惑度这一简单指标令人意外且有价值；reasonableklout 则关注不同机构能否在共同留出集上报告可比较的预训练进展。

### [不确定时，如何通过快速试错获取反馈](https://seangoedecke.com/when-in-doubt-flail-about/) ⭐️ 6.0/10

rss · Sean Goedecke · 11月23日 00:00

**「背景」** 面对缺乏明确方向、无法判断什么措施有效的技术或组织问题，谨慎等待完整分析往往只会延误行动。作者主张采用一种看似反直觉的“乱试”策略，但前提是必须快速接触现实、密切观察反馈，并及时放弃没有正向结果的方案，否则这种做法很容易损害个人声誉。

**「方案」** 作者将有效试错概括为三个相互关联的动作：同时尝试多个不同方案，从专家和现实结果中敏锐获取反馈，以及毫不拖延地淘汰表现不佳的方案。多方案并行既能提高发现有效路径的概率，也能降低对单一计划的沉没成本，因为团队不必执着于让某一个想法成功。

这种方法适用于三类场景。产品探索中，团队应围绕尚未验证的价值空间广泛尝试，找到有牵引力的方向后再集中投入，例如作者在 GitHub Models 项目中，许多功能和集成效果不佳，但允许通过 GitHub Actions 令牌运行 AI 推理的方案最终成为 Continuous AI 的起点。工程改进中，面对复杂、庞大或高度优化的系统，与其先全面理解再提出建议，不如并行实施多项推测性变更，通过实际效果筛选，再深入研究有效方案为何奏效。组织问题中，负责人可以尝试自动化手工工作、临时接管任务或提出长期计划等干预手段，但必须对反馈尤其敏感，否则持续推进无效行动会把团队的不满和怨气集中到自己身上。

作者还指出，“乱试”在主观感受上确实像反复失败，因此工程师需要预先接受这种不适，把它视为积极行动和获取认知的信号，而不是陷入困境的证据。

**「启示」** 当信息不足时，最有效的工程判断往往不是等待唯一正确答案，而是并行探索、敏锐读取反馈并快速放弃弱方案。乱试并非盲目消耗资源，而是一种以低成本接触现实、降低承诺风险并建立组织信任的决策方式。
